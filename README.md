# 双端语音交流方案

一个能跑在自己家里的实时语音通道：**手机当话筒和喇叭，算力那台当耳朵嘴巴，另一台当脑子**。
（本项目由**台式主机**跑边缘侧、**笔记本**跑大脑侧，两台机器共同运行、共同维护。）

- **边缘侧**（有 GPU 的那台）：音频流进来 → 唤醒 → VAD 判停 → ASR → 问大脑 → TTS → 音频流回去。
- **大脑侧**（另一台，可选同机）：接一段文字，吐一段文字；人格、记忆、历史都在这一侧。
- **手机端**：只收发音频，不判断、不存状态。

## 谁在维护这套东西

**本项目由一台笔记本和一台台式主机共同运行、共同开发**——两边的代码、协议、文档都在这个仓库里
一起改；任何一次协议变更都要两边同时能跑，单边改完就算没做完。

| 角色 | 机器 | 负责 |
|---|---|---|
| 边缘侧 | **台式主机**（Windows + NVIDIA GPU） | 8780 语音枢纽、9884 VAD、9883 ASR、9880 TTS、KWS 唤醒、看门狗 `hub.py`、relay 8781/8778、信箱 8790 |
| 大脑侧 | **笔记本**（Windows，常挂在主机后面） | 8777 大脑：人格、记忆、历史、声纹；只接文字吐文字，不碰音频 |
| 采集端 | 手机（Android APK） | 录音/播放、只渲染服务端 `state` |

两边的分工原则是「**音频归主机，人格归笔记本**」：音频（唤醒/VAD/ASR/TTS）与状态机全在主机上，
一次都不跨机；真正的「她是谁」全在笔记本上，跨机只走一段文字。这样换机器、换网络、
笔记本重启，都不会把已训好的音色和链路拆散。

> 两台机器的相对地址每次开机都可能变（`192.168.137.x`），所以边缘侧不写死大脑地址，
> 而是开机后扫段自动发现；relay 同理。见 `docs/PITFALLS.md` 的跨机网络一节。

```
┌──────────┐  PCM16LE 16k, 0.5s/包   ┌──────────────────────────┐   SSE 逐句文本   ┌──────────────┐
│ 手机 App  │ ───────────────────────▶ │ 边缘侧(台式) :8780        │ ───────────────▶ │ 大脑侧(笔记本)│
│ (录音/播放)│ ◀─────────────────────── │ 9884 VAD · 9883 ASR       │ ◀─────────────── │ :8777         │
└──────────┘   事件 + wav/base64 段    │ 9880 TTS · KWS 唤醒       │   按句流式返回   └──────────────┘
                                      └──────────────────────────┘
```

## 这套东西解决了什么

1. **听/想循环**——用服务端状态机（idle → wake → recording → thinking → speaking）替代客户端按音量猜。
   客户端只渲染 `state`，不判定。
2. **回话慢**——判停后先出垫音（filler），正文按句流式分段推；端到端首段音频 0.7~1.7s。
3. **播放声被当成输入**——播放期客户端真闭麦 + 服务端 `playing` 标志双保险；VAD 另有
   「短段当噪声」「能量静止 1.8s 强制收尾」「单段 12s 上限」三道闸。
4. **误唤醒**——KWS 分数只是「像不像」；命中后用 ASR 复核 2.5s 缓冲里的文本，20ms 判真假。
5. **跨机地址漂移**——大脑在 ICS/热点后面时 IP 每次开机可能变；边缘侧自动扫段发现，
   relay 同样自适应，不需要改配置。

## 快速开始（边缘侧）

```bash
# 1. Python 3.12
python -m venv venv && venv/Scripts/pip install -r requirements.txt

# 2. 三个模型服务（自行准备，见 MODELS.md）
#    - GPT-SoVITS api_v2.py  (9880, TTS)
#    - FunASR paraformer      (9883, ASR)
python vad/vad_server.py                     # 9884（本仓）

# 3. 配好大脑地址与参考音
export VOICE_BRAIN=http://192.168.137.10:8777
export VOICE_REF=/path/to/ref.wav VOICE_PROMPT=/path/to/ref.txt
python edge/voice_edge.py                    # 8780

# 4. 看门狗（可选）
python hub/hub.py --once                     # 单次巡检
```

## 环境变量（全部可覆盖，代码里没有必须改的常量）

| 变量 | 默认 | 说明 |
|---|---|---|
| `VOICE_BRAIN` | 空 | 大脑基址，如 `http://192.168.137.10:8777` |
| `VOICE_ICS_PREFIX` | `192.168.137.` | 大脑地址漂移时扫这个网段 |
| `VOICE_VAD` / `VOICE_ASR` / `VOICE_TTS` | `127.0.0.1:9884/9883/9880` | 三个本地服务 |
| `VOICE_REF` / `VOICE_PROMPT` / `VOICE_PROMPT_LANG` | 空 | TTS 参考音、其文本、语言 |
| `VOICE_KWS_V1` / `VOICE_KWS_HEY` | 空 | openWakeWord 模型路径（留空=关唤醒，只认 `force`） |
| `VOICE_KWS_TH_V1` / `VOICE_KWS_TH_HEY` | `0.93` / `0.99` | 唤醒阈值（**别照抄，按自己的模型标定**） |
| `VOICE_KWS_ASR` | `1` | 命中后是否用 ASR 复核 |
| `VOICE_LP` | `0` | 段内低通截止（Hz），0=关 |
| `VOICE_DUMP_DIR` | 空 | 唤醒留证 wav 落盘目录 |
| `MAIL_KEY` | 空 | 信箱口令（空=拒绝所有写操作） |

## 设计取舍

- **状态只在一处**：谁判「说完了」、谁维护「这一轮」，只在边缘侧决定；手机端只负责播放和收包。
- **协议只有一份**：以 `docs/protocol.md` 为准，两边都不私改。
- **墊音**：判停之后立刻回一小段固定语音，别让用户干等；正文合成好了再接上。
- **可打断**：播报期间仍然收包，但只认「退下 / 别说了」这类口令，其余一律丢。
- **上下文**：由大脑侧维护（参考实现滚动 12 条 ≈ 6 轮），边缘侧不存对话。

## 不包含什么

- **模型权重**（TTS 的 GPT/SoVITS、唤醒 onnx、ASR）——见 `MODELS.md`，自己下。
- **人格与记忆**——在大脑侧。
- **商业音色**——本仓不带任何以他人声音训练出的权重，见 `CREDITS.md`。
