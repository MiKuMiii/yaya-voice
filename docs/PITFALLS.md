# 踩过的坑（按「症状 → 真因 → 解法」写，都是真机上撞出来的）

> 这份清单比代码值钱：代码只是其中一种走法，坑是所有走法都会撞的。

## 一、听/想循环与播放声

**1. 雅雅被自己的声音打断**
症状：她说完一句，手机立刻又把这段播出来的声音当成用户说话。
真因：播放期「停发但不停采」，VAD 一直在收 TTS 的尾巴。
解法：客户端在播放期**真闭麦**（`rec.stop()` + 清缓冲），播完等 250ms 再开麦，开麦头 300ms 丢弃；
服务端同时用 `playing:true` 丢包 + 清 VAD，双保险。

**2. more 段里出现整段静音（0.30s peak=0）**
真因：TTS 按句合成，每句自带首尾静音；0.9s 硬切正好切在两句之间的空白上。
解法：切段前在 ±150ms 内按 10ms 窗找**最安静处**切；`peak < 300` 的段直接丢，不发。

**3. 「刚说两句就被打断」**
真因：只喊了「雅雅」就停顿，唤醒词自己被 VAD 收尾成一轮 → 当成用户说话送大脑 → 大脑无内容 →
回垫音 → 手机进入播放期闭麦 → 后面那句没采到。
解法：① 判完 `end` 后加 700ms 悔棋窗口，有人声就作废；② 送大脑前把唤醒词剥掉，
剥完只剩唤醒词就不算一轮；③ 静音收尾 1200ms→1800ms。

**4. wake 之后整轮收不到 end**
真因：`STREAM_REOPEN_GAP_S` 太大（1.5s），判完后客户端继续发的活包全落进「丢弃窗口」。
解法：把它收到 0.35s；悔棋窗口才有机会生效。

## 二、VAD / ASR

**5. 一轮有 6s 音频却被判 timeout、`seg:[]`、没有文本**
真因：`self.segs` 只装**已闭合**的段；VAD 卡在 `is_speaking` 时它永远是空，于是「累计 6s ⇒ 没人声 ⇒ 丢掉整轮」。
解法：改用 `spoke` 标记（见过任何 speaking 就算有人声）；另加静音强制收尾（1.8s）与
单段上限（12s），收尾时 `finalize()` 把开着的段 flush 出来。

**6. 离线 `/vad` 的结果被流式那路污染**
真因：`DynamicStreamingVAD` 会改共享 `model.vad_opts`。解法：流式单独一个 `AutoModel` 实例。

**7. 参数别信默认**
`DEFAULT_SILENCE_SCHEDULE` 是「说满 5s 后要 2s 静音才收尾」，对短句太慢。
自定 `[(4000,700),(8000,600),(15000,500),(30000,450),(inf,400)]`。

## 三、唤醒

**8. 分数 0.999 也不是唤醒词**
实测四次误唤醒：`「待会我去。」0.994`、`「去哪儿了？」0.999`、`「好了吗？」0.997`、`「哎呀。」0.999`。
真唤醒的转写一律是「雅雅。」/「丫丫。」。
解法：命中后用 ASR 复核滚动缓冲最后 2.5s 的文本（20ms），文本不像唤醒词就否掉；空文本放行。

**9. 音量门限别按「当包峰值」算**
KWS 打分滞后 0.4~0.9s，唤醒词说完那几包已经是静音（peak=0），按当包判会把真唤醒全丢掉。
解法：取 800ms~2s 窗口内的**峰值最大值**。

**10. 唤醒词的补喂会自己收尾**
唤醒时补喂前 2s 音频，VAD 把「雅雅」收尾成一轮 → 该 sid 变 closed →
后续活包落进丢弃窗口 → 整轮没有 end。
解法：补喂过程中若拿到 end，就把那段文本存成 `prefix`，立刻 `vad_reset` 重开会话，
在最末 end 时拼回去（`prefix + "，" + text`）。

**11. 阈值不能照抄别人的**
同一对模型，换录音设备/降噪开关，分数分布就变。「我的阈值 0.93」只对我的麦克风成立。

## 四、TTS

**12. 参考音不是训练数据**
参考音 3~10s 只决定**这一次**的音色；要改「这个人」得微调，需要 10 分钟以上说话干声。
拿别的声音当参考音，出来的就是**那个人**（实测：换中文参考音，输出 F0 从 276Hz 掉到 115Hz）。

**13. 提示文本必须与参考音逐字对应**
对不上时输出会「半句」或直接念崩（实测只剩「今天。」）。歌词拿不到就别猜。

**14. 参考音太长/太轻都会让流式断**
- 超过 10s：合成中途 `ChunkedEncodingError: InvalidChunkLength(got length b'', 0 bytes read)`
- 原始 rms 只有 0.004（-48dBFS）：同样断。先归一到峰值 0.85 再喂。

**15. 采样参数决定语速，不是模型**
同一句 14 字：`top_k/top_p/temp = 5/1.0/1.0` → 3.36s；`10/0.8/0.8` → 3.72s；`20/0.6/0.6` → **15.32s**。
seed 固定后完全可复现。听着「特别慢」先看参数，别怀疑模型。

**16. `speed_factor` 不改音色**
1.0/1.4/1.6/1.8 输出 F0 恒为 275.9Hz，不会娃娃音；改的是时长（0.56 → 0.34 秒/字）。

**17. 原生 9880 没有默认参考音**
裸调 `GET /tts?text=…` 会 500（不是 400），因为它缺 `ref_audio_path`/`prompt_text`。
要包一层（本仓 `edge/voice_edge.py` 的 `/tts`）。

## 五、跨机与网络

**18. 隔壁在 ICS/热点后面，IP 每次开机都可能变**
Windows ICS 的 DHCP **没有 MAC 绑定**，固定 IP 做不到。
解法：服务端扫 `x.x.x.0/24:端口` 用业务接口认人（`/mail/health` 的 `me` 字段），缓存 5 分钟。

**19. ping 不通不代表对面死了**
对面挡 ICMP 很常见。判活用 TCP connect 或业务接口。

**20. 裸 TCP 中转没有 `/health`**
把 `8778/health` 拿去探活，会被原样转给对面；对面一停，看门狗就把**好的**中转杀掉重起。
解法：中转用 `tcp` 探活，别用 HTTP。

**21. 探活自己慢会被看门狗误杀**
`/health` 里做了 254 个地址的扫描 → 响应 5s → 看门狗 2.5s 超时 → 判死 → 杀 → 重启 → 再判死。
解法：`/health` 只读缓存（后台线程定期探），本地三件并行探且各自 0.8s 超时；看门狗
**连续两次不健康才动手**。

**22. SYSTEM 身份起的服务，普通权限杀不掉**
`Stop-Process` 之后端口还在听，新进程 `[Errno 10048]`。
解法：写一个 `restart.txt` 给看门狗，由它（SYSTEM）来杀。

## 六、Windows / 工具链

**23. 便携版 Python 的 `._pth` 会吃掉 PYTHONPATH**
`runtime/python39._pth` 里只列了 `python39.zip` 和 `.`，`PYTHONPATH` 被彻底忽略 →
`ModuleNotFoundError: No module named 'text'`。解法：写一个 shim，先 `sys.path.insert` 再 `runpy.run_path`。

**24. PowerShell 5.1 的 `Set-Content -Encoding UTF8` 会加 BOM**
后果：`ast.parse` 报 `SyntaxError: invalid non-printable character U+FEFF`；
`open(..., encoding="utf-8")` 读到的第一个字符是 BOM，喂给 TTS 直接 400。
解法：写文件用 `[System.IO.File]::WriteAllText($p,$s,(New-Object System.Text.UTF8Encoding($false)))`；
读配置用 `encoding="utf-8-sig"`。

**25. `Test-Path 'x' -and (...)` 少括号**
报「找不到与参数名称"and"匹配的参数」。参数模式里不能直接写表达式。

**26. `New-ScheduledTaskTrigger -Once -RepetitionDuration ([TimeSpan]::MaxValue)` 失败**
`任务 XML 包含格式不正确或超出范围的值。(8,42):Duration:P99999999DT23H23H59M59S`。
改用 `schtasks /sc minute /mo 2`。

**27. 提权窗口的输出不回父进程**
`Start-Process -Verb RunAs` 的 stdout 拿不到。解法：脚本里自己写日志文件，父进程读文件。

**28. `%` 在 PowerShell 命令里被 Python 格式化吃掉**
`pids_by_marker` 里写 `'%python%'` → `unsupported format character 'p'`。写成 `%%python%%`。

**29. 后台命令用 `| Out-String` 会缓冲到进程结束**
长跑监控看不到实时日志。要么不用，要么 `-Streaming` 逐行输出。

## 七、验证方法（别自己骗自己）

**30. 分帧对齐错了，频谱数字全错**
样本长度是 1280 的整数倍（80ms 帧）说明拿到的是「按帧切的环形缓冲」，不是「以某个时刻为中心」。
对齐错 1 个字节，7kHz 以上功率占比能从 1.5% 变成 53%。

**31. 高频「刺耳」多半是口径问题**
「7kHz 以上幅值占比」量**棚录真人**也报 10.97%；能分开正常/异常的是功率占比（真人 0.72% / 本仓 1.5%）。
先把口径对齐，再谈降噪。

**32. ASR 只收 16k**
32k PCM 直喂 9883 → `{"ok":false,"error":"expect 16000Hz PCM16LE"}`。先重采样。

**33. 别人的分数先复现再采信**
对面报「0.85~0.89」，我这边同一批文件跑出来 0.000~0.002 —— 因为样本里根本没有那个词。
**先转写，再看分数。**

**34. 测试脚本自己会骗你**
「验证『延后 N 秒才发』的路径」时，静音尾巴必须比窗口长，否则永远等不到那个包。
读日志前先看 `LastWriteTime`，别拿「还没落盘」当成「程序卡住」。

## 八、语音这条线特有的时间账

**35. 垫音慢 1.1s 不一定是服务端**
服务端「垫音延后随下一个上行包带回」+ 客户端「收到垫音才开始轮询」= 白等一个包（0.5s）。
客户端改成**常开轮询**（400ms），垫音从 1820ms 掉到 700~800ms。

**36. 「退下」被听成「退一」**
`退一下吧` → ASR 给的是 `退一下吧`/`退一下吧`，旧词表只有「退下」。
解法：强口令不看句长（退下/退一下/退一/关掉/关闭语音…），弱口令（结束/再见/晚安…）仍要求 ≤6 字。

**37. 别把 `me` 字段当身份指纹**
对端把 `me` 从「电脑」改成「笔记本」，我据此推断「换机器了」并提醒搬数据 —— 主人说只是改名。
判断换机要看进程启动时间/文件连续性，或者直接问。

**38. 走 SSH 推 GitHub：反斜杠会被吃、环境变量会盖住配置**
`GIT_SSH_COMMAND='ssh -i C:\Users\me\.ssh\key'` 会让 ssh 报
`Identity file C:Usersme.sshyaya_github not accessible` —— 这串 git 还要再拆一次命令行，
`\U`、`\.` 都被当转义吃掉了。更坑的是：改成正斜杠写进 `core.sshCommand` 之后仍然失败，
因为 `GIT_SSH_COMMAND` 环境变量优先级更高，得先 `Remove-Item Env:GIT_SSH_COMMAND`。
在 github.com:443 被掐的网络上，`ssh://git@ssh.github.com:443/<owner>/<repo>.git` 是可行通道。
